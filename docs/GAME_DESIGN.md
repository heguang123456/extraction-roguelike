## 0. 术语定义（P0，全文统一）

| 术语 | 定义 |
|---|---|
| **runId** | 每局唯一 ID，创建 RunState 时生成：`run_${timestamp}_${4位随机}`；用于幂等结算与出发事务 |
| **结算（settlement）** | 单局结局的一次性处理：SUCCESS / DEAD / MIA；结果写入 RunState.settlement 并原子反映到 Profile；**同一 runId 全局只结算一次** |
| **变现（cash out）** | 物品按 `value` 折算为资金并销毁实物；每件物品最多变现一次 |
| **入库（store）** | 物品移入 `profile.stash`（保留实物，医疗品可堆叠合并）；每件物品最多入库一次 |
| **补足（floor top-up）** | 营地阶段开始（新档首次加载 / 结算回到营地）时，若 `money < floor` 则补足到 `floor`；**每个营地阶段只触发一次**（§10.4） |
| **物品归属位置** | `stash`（仓库）\| `weapon`（装备栏-武器）\| `armor`（装备栏-护甲）\| `run.inventory`（局内背包）\| `run.weapon/run.armor`（本局携带）。任意时刻一件物品只属于一个位置 |
| **暂停/补偿（pause/resume）** | 统一时间管理：暂停记录 `pausedAt` 开始时刻，恢复时 `deadline += now − pausedAt`；**多种暂停原因重叠时只补偿一次**（§15.3） |
| **弹层暂停** | 模态弹层（替换弹层、结算弹层）打开 → 进入暂停态（倒计时冻结），关闭 → 恢复 |
| **金箱（gold crate）** | 高价值箱子：品质上移、开箱需引导、精英守卫、可绕开（§4.4） |
| **出发事务（startRun）** | 从营地进入局内的跨存档数据转移，持久化顺序与异常恢复有明确规定（§15.4） |

## 1. 游戏概述

- **类型**：俯视角 roguelike「搜打撤」（参考逃离塔科夫/逃离鸭科夫）微信小程序，离线单机版。
- **一句话**：进入随机小地图，限时搜刮物资、击杀敌人，在倒计时结束前抵达撤离点带出战利品；死亡或超时则损失本局所得与携带装备。
- **目标体验**：单局 3–5 分钟：搜刮期待、遭遇紧张、撤离倒计时压迫、好装备惊喜。
- **平台**：微信小程序（Taro + React，本地存档）；H5 用于开发预览。
- **P0 铁律**：单局只结算一次；物品任意时刻只属于一个位置；出发与结算的跨存档转移均崩溃安全；所有规则可验证。

---

## 2. 核心循环

```
营地（整理装备/仓库/商店/升级/成就）
  → 开始行动（出发事务：自动装配 武器+护甲+至多 supply 个医疗品，进入地图）
  → 局内：随机地图 → 搜刮箱子（普通即时 / 金箱引导） → 遭遇战斗 → 抵达撤离点
  → 结局：
      ✅ SUCCESS → 装备/医疗入库仓库 + 杂物变现为资金
      💀 DEAD / ⏰ MIA → 本局所有物品销毁
  → 回到营地（结算应用 + 资金补足）→ 出售/商店/升级/成就 → 再来一局
```

---

## 3. 单局流程与限时撤离

1. **开局**：`EXTRACT_SECONDS = 240` 秒倒计时启动；HUD 顶部显示剩余时间与当前战利品估值（`run.inventory` 中物品 value 合计，不含已装备物）。
2. **搜刮**：进入普通箱子格自动开箱（即时）；金箱需引导 **17 tick（2040ms）**（§4.4）；背包满进入替换弹层（§13.6）。
3. **战斗**：摇杆移动 + 攻击按钮；远程敌人有视线与保持距离行为（§7.3）；精英有冲锋预警（§7.3）。
4. **撤离**：抵达撤离点格进入 3 秒引导进度；被敌人击中进度回退 50%；离开撤离点格进度清零。
5. **结算**（幂等，§12）：
   - **SUCCESS**：`run.inventory` 中**装备类（武器/护甲）与医疗品 → 入库**；**杂物类 → 变现**；`run.weapon/run.armor` → 入库；`extractions++`。
   - **DEAD**：`run.inventory` 与 `run.weapon/run.armor` **全部销毁**；仓库已有物品、资金、升级、成就保留；`deaths++`。
   - **MIA**（倒计时归零未撤离）：与 DEAD 相同，文案显示「撤离超时」。
   - 任何结局 `runs++`、HP 回满、清空局内存档、回到营地并触发一次补足（§10.4）。

**验收（§3）**：SUCCESS 后物品每件只入账一次（变现 XOR 入库）；DEAD/MIA 后仓库物品不受影响；结算后无法再操作本局。

## 4. 地图生成规格（P0）

### 4.1 参数

| 常量 | 值 |
|---|---|
| GRID_W / GRID_H | 13 / 13 |
| ROOM_COUNT_MIN / MAX | 2 / 4（推荐中位 3） |
| ROOM_SIZE_MIN / MAX | 4 / 6 |
| 房间间隔 | ≥1 格墙 |
| 普通箱子/房间 | 1–2（1–3 件掉落） |
| 金箱/局 | 0–1（§4.4） |
| 普通敌人总数 | `rooms × 2`（近战 65% / 远程 35%，**不含精英**；金箱房额外 1 远程守卫**计入此配额**） |
| 精英 | **每局固定 1 个**：有金箱 → 金箱所在房间；无金箱 → 最后房间 |

### 4.2 生成步骤（P0：先放物，后验证）

1. 在 13×13 网格上依次随机放置 2–4 个矩形房间（位置/尺寸随机，间隔 ≥1 格墙；重叠或越界 → 该房间重试 ≤20 次，仍失败 → 全局重试）。
2. 按房间顺序用 L 形走廊连接相邻房间（1 格宽，只打通墙体，不改房间内部）。
3. **放置物品与敌人**：
   - 每房间放 1–2 普通箱子（不放出生点/撤离点中心格）。
   - 掷金箱：80% 概率生成 1 个，置于房间顺序靠后（≥ 第 2 房间）的角落格（不落出生点/撤离点格）；该房间为「金箱房」。
   - 放置普通敌人：先为金箱房分配 1 名远程守卫（计入配额），其余普通敌按近战 65% / 远程 35% 分布到各房间。
   - 放置精英（§4.1 位置规则）。
4. **连通性验证（BFS）**：出生点（第一房间中心）→ 撤离点（最后房间中心）、所有箱子格、所有敌人格**均可达**；任一不可达 → 全局重试（回到步骤 1，上限 50 次）。
5. **兜底**：50 次仍失败 → 使用内置预设地图（固定 3 房间、含 1 金箱），保证永不阻塞。

### 4.3 验收指标（P0）

| 指标 | 通过条件 |
|---|---|
| 连通性 | 连续生成 1000 次：出生点→撤离点、全部箱子格、全部敌人格可达，无重叠房间、无孤立房间 |
| 地图重试率 | 1000 次生成中因连通性失败触发全局重试的次数占比 < 5% |
| 备用地图使用率 | 1000 次生成中触发预设兜底 0 次 |
| 精英数量 | 1000 次生成精英恒为 1 个，位置符合 §4.1 |
| 金箱约束 | 金箱不落在出生点/撤离点中心格；金箱房必有 1 精英 + 1 远程守卫，且远程守卫计入普通配额 |

### 4.4 高价值箱子与守卫（P1）

| 项 | 规则 |
|---|---|
| 数量 | 每局 0–1 个（80% 出现），位置在房间顺序靠后（≥ 第 2 房间）的角落格，且不位于撤离点格 |
| 掉落 | 品质概率上移：white 10% / green 10% / blue 40% / purple 30% / gold 10%（1–2 件） |
| 开箱 | 需引导 **17 tick（2040ms）**；离开箱子格或受击则进度清零；引导期间可被守卫攻击；开箱状态由 `Crate.state` 管理（§13.7） |
| 守卫 | 金箱房固定 1 精英（即全图唯一精英）+ 1 远程（计入普通配额）；守卫可绕开 |
| 风险 | 金箱是可选目标：玩家可绕开不搜 |

**验收**：金箱开箱引导可被打断且按 tick 计数；守卫行为与普通敌人一致；玩家可完全绕开金箱完成撤离；精英恒为 1。

## 5. 玩家与操作（P0/P1）

### 5.1 时间单位（P0：全 tick 制）

- **全游戏时间以 tick 为单位，1 tick = `TICK_MS = 120`ms**；不存在独立于 tick 的毫秒冷却。
- 所有冷却/间隔/引导以 tick 数定义；敌人行动每 **4 tick**（480ms）；金箱引导 **17 tick**（2040ms）。

### 5.2 操作

| 操作 | 规则 |
|---|---|
| 移动 | 虚拟摇杆，格子制；每 tick 最多移动 1 格；**优先单轴**；撞墙/越界不移动；松手即停 |
| 攻击 | 攻击按钮；冷却 = 武器最终攻击间隔（tick 数）；自动锁定目标（§8.1） |
| 治疗 | 治疗按钮；冷却 5 tick（600ms）；自动消耗 `run.inventory` 中第一个医疗品（先绷带后医疗包），触发堆叠拆分（§13.5） |
| 开箱 | 普通箱子：进入格自动开箱；金箱：进入格开始引导 17 tick（§13.7） |
| 弹层 | 替换弹层/结算弹层打开 → 暂停态（弹层暂停，§15.3） |

### 5.3 触控与渲染策略（P1）

- **模拟与 UI 分离**：全部模拟在 `useRef` 状态中按 tick 推进；React 状态节流快照（默认每 2 tick 一次 = 240ms，关键事件如受伤/掉落/结算立即同步）。
- 倒计时显示由 `deadline` 绝对时间戳计算，不逐帧 setState。
- 摇杆：`onTouchStart` 缓存圆心（`boundingClientRect`），`onTouchMove` 算方向（deadzone 0.25），`onTouchEnd` 归零。
- 攻击/治疗按钮单击触发；长按连发为 P2。
- 切后台：`onHide` 进入暂停态；`onShow` 走 §15.3 恢复。

### 5.4 基础属性

- 基础 HP `100`（可升级至 150）；基础背包 10 格（可升级至 20）；徒手伤害 `4`。

### 6.1 品质（稀有度）

| 品质 | key | 品质伤害倍率 | 品质防御倍率 | 词条数 | 价值系数 | 普通箱概率 | 金箱概率 |
|---|---|---|---|---|---|---|---|
| 普通 | white | ×1.00 | ×1.00 | 0 | ×1.0 | 45% | 10% |
| 优良 | green | ×1.15 | ×1.10 | 1 | ×1.5 | 30% | 10% |
| 精良 | blue | ×1.30 | ×1.20 | 1–2 | ×2.5 | 17% | 40% |
| 史诗 | purple | ×1.50 | ×1.30 | 2 | ×4.0 | 6% | 30% |
| 传说 | gold | ×1.80 | ×1.40 | 3 | ×7.0 | 2% | 10% |

- 品质色：white `#cfd3dc` / green `#4caf50` / blue `#2196f3` / purple `#9c27b0` / gold `#ffc107`。
- 掉落流程：**先按来源（普通箱/金箱）掷品质，再在适用模板中随机选模板**；普通敌人 20% 掉 1 件（普通箱概率表）；精英 100% 掉 1 件且 **blue 保底**（金箱概率表）。

### 6.2 模板与战斗定位（P1）

| 模板 | key | 基础伤害 | 基础射程 | 基础攻击间隔(tick/ms) | 基础价值 | 定位 |
|---|---|---|---|---|---|---|
| 手枪 | pistol | 10 | 3 | 6 (720) | 120 | 均衡 |
| 霰弹枪 | shotgun | 20 | 2 | 8 (960) | 260 | 近距爆发 |
| 步枪 | rifle | 16 | 4 | 7 (840) | 400 | 远程压制 |

| 模板 | key | 基础防御 | 基础价值 | 定位 |

### 6.3 词条

| 词条 | key | 适用 | 类型 | 效果 | 上限 |
|---|---|---|---|---|---|
| 锋锐 | sharp | 武器 | 百分比 | 伤害 +20% | 3 次 |
| 长管 | longbarrel | 武器 | 固定 | 射程 +1 | 2 次 |
| 速射 | rapid | 武器 | 冷却缩减 | 攻击间隔 -15%（作用于 tick 数） | 总缩减 ≤ 40% |
| 吸血 | lifesteal | 武器 | 固定 | 每次攻击回复 2 HP | 2 次 |
| 坚固 | sturdy | 护甲 | 固定 | 防御 +2 | 2 次 |
| 活力 | vitality | 护甲 | 固定 | 局内最大生命 +10 | 2 次 |

### 6.4 属性计算公式（P0）

```
最终伤害 = 模板基础伤害 × 品质伤害倍率 × (1 + Σ伤害百分比词条)          // 向下取整
最终射程 = 模板基础射程 + Σ射程固定词条                                  // 整数
最终攻击间隔(tick) = max(4, ceil(模板基础间隔 × (1 − 总冷却缩减)))      // 总缩减 = 1 − Π(1−单条)，上限 40%
最终防御 = 模板基础防御 × 品质防御倍率 + Σ防御固定词条                   // 向下取整
局内最大生命 = 营地最大生命 + Σ活力×10                                  // 下限 1
每次攻击吸血 = Σ吸血×2
```

- 品质倍率**仅作用于伤害与防御**，不作用于射程/冷却/吸血/生命。
- 实例价值：`value = round(模板基础价值 × 价值系数)`（词条不改变价值）。
- 出售价：`sellPrice = floor(value × 0.5)`。

### 6.5 医疗与杂物

| 模板 | key | 效果 | 基础价值 | 结算类别 | 堆叠 |
|---|---|---|---|---|---|
| 绷带 | bandage | 治疗 15 | 40 | 医疗（入库） | 可 |
| 医疗包 | medkit | 治疗 35 | 100 | 医疗（入库） | 可 |
| 零件 | parts | 杂物 | 50 | 杂物（变现） | 否 |
| 芯片 | chip | 杂物 | 120 | 杂物（变现） | 否 |
| 金币堆 | coin_stack | 杂物 | 30 | 杂物（变现） | 否 |

> 结算类别决定 SUCCESS 时的处理（§13.4）：装备类（武器/护甲）与医疗类入库；杂物类变现。

## 7. 敌人系统（P0/P1）

### 7.1 数值与分布

| 类型 | key | HP | 伤害 | 射程 | 分布 | 掉落 |
|---|---|---|---|---|---|---|
| 近战 | melee | 25 | 8 | 1 | 普通敌 65% | 20% 掉 1 件 + 10–30 零钱 |
| 远程 | range | 18 | 6 | 4 | 普通敌 35% | 20% 掉 1 件 + 10–30 零钱 |
| 精英 | elite | 60 | 15 | 1 | **每局 1 个**（金箱房，无金箱则最后房间） | 必掉 1 件 blue+，不掉零钱 |

- 普通敌人总数 = `rooms × 2`（不含精英）；金箱房 1 名远程守卫计入该配额。

### 7.2 行动节拍（P0）

- 敌人行动固定**每 4 tick 一次**（`ENEMY_TICK = 4`，= 480ms），由主循环计数触发（§12.3），**不设独立定时器**。
- 伤害公式：对玩家伤害 = `max(1, 敌人伤害 − 玩家最终防御)`。

### 7.3 行为（P0：优先级互斥、可执行）

- **近战**：每行动回合，① 若玩家在射程 1 且相邻格可达 → 攻击；② 否则 BFS 朝玩家移动一格；③ BFS 无路径 → 原地。
- **远程**：每行动回合按优先级（**互斥，前一分支成立即执行，不继续判断**）：
  1. 玩家距离 < 2 且有视线 → **后退一格**（BFS 选择远离玩家的可通行格；无可行后退格则原地）；
  2. 玩家在射程 4 内且有视线 → **攻击**；
  3. 否则 → BFS 朝玩家移动；
  4. BFS 无路径 → 原地。
- **精英**：基础行为同近战；附加「蓄力冲锋」：当精英与玩家曼哈顿距离 ≤ 3 时，每 **3 个敌人行动回合**发动一次——第 1 回合显示红色预警（不变位），第 2 回合沿冲锋方向直线移动 2 格；冲锋路径经过玩家所在格 → 玩家受击（按 §7.2 公式）。**冲锋方向**：玩家与精英同行取水平、同列取垂直；否则取 `|dx| ≥ |dy|` 的水平（否则垂直）；冲锋格遇墙或不可通行 → **原地取消**（不半路停）。
- **视线判定**：玩家与敌人**同行或同列**，且之间所有格可通行（无墙）→ 可视；斜线不可视。

### 7.4 精英与金箱守卫（P1：可绕开）

- 精英**非撤离前置条件**：玩家可不杀精英，直接进撤离点引导（风险：引导期间被精英攻击打断）。
- 击杀精英：必掉 1 件 blue+ 装备（可带出）；金箱守卫精英同规则。

**验收（§7）**：敌人不穿墙；远程不隔墙攻击且优先保持距离（可实测：贴近远程敌人时它先后退再攻击）；精英冲锋方向可预测且有预警；玩家全程可走位规避近战与冲锋；不杀精英可撤离；每局精英恒为 1。

## 8. 战斗规则（P0）

### 8.1 攻击目标筛选

- 攻击命中判定：目标在最终射程内（曼哈顿距离 ≤ 射程）、与玩家**同行或同列**且中间无墙、目标存活。
- 多目标筛选：**先取曼哈顿距离最小；距离相同取 HP 最低**；无合法目标则本次攻击空挥（进入冷却）。

### 8.2 冷却（tick 制）

- 攻击冷却：按下攻击按钮即进入冷却，冷却 tick 数 = 武器最终攻击间隔（§6.4），冷却期间按钮无效；徒手固定 6 tick。
- 治疗冷却：5 tick（600ms）。
- 攻击与移动互不阻塞；暂停态时冷却冻结。

### 8.3 结算优先级

- 同一 tick 内：**DEAD 判定先于 SUCCESS**（死亡即终止）；**SUCCESS（引导完成）先于 MIA**（倒计时归零当 tick 已完成引导算成功）。
- 玩家与敌人同时死亡：玩家死亡优先，按 DEAD 结算。

**验收（§8）**：多敌情况下攻击目标选择可复现；冷却 tick 数与公式一致；极端同 tick 场景结局唯一。

## 9. 撤离规则（P0）

- 进入撤离点格：开始引导，`EXTRACT_CHANNEL_MS = 3000` 进度条。
- **离开撤离点格 → 进度清零**；**被敌人击中一次 → 进度回退 50%**（可多次）。
- 引导期间可移动/攻击；暂停态时进度冻结。
- 倒计时 `EXTRACT_SECONDS = 240` 秒，从开局时刻起算；暂停/恢复按 §15.3。
- 单撤离点（最后房间中心）；MVP 不生成多个撤离点（P2）。

## 10. 营地系统（P0/P1）

### 10.1 界面区块

1. **状态面板**：最大 HP / 当前武器与护甲属性 / 资金 / 战绩（撤离、死亡、总局数）/ 成就。
2. **装备栏**：武器 + 护甲（品质色 + 词条），可卸下（回仓库）。
3. **仓库（stash）**：网格展示；点击弹层：装备 / 出售（`sellPrice`，二次确认）/ 丢弃（二次确认）。
4. **商店**：固定商品（§10.3），资金购买入仓库。
5. **升级区**：4 条永久升级（§10.5）。
6. **成就区**：里程碑计数与一次性奖励（§10.6）。
7. **开始行动**（出发事务，§15.4）：**手动装配优先**——玩家已装备则沿用；`weapon` 为空才自动装配仓库 `value` 最高武器；`armor` 同理（均无则徒手/无甲）；从仓库扣除 `supply` 个医疗品（绷带优先，触发堆叠拆分）入 `run.inventory`；背包容量 = `10 + inv×2`。

### 10.2 初始玩家状态（P0）

| 项 | 值 |
|---|---|
| 初始 HP | 100 |
| 初始资金 | 0（首次加载营地触发一次补足） |
| 初始武器 | 白手枪 1 把（`pistol` white 0 词条） |
| 初始护甲 | 无 |
| 初始仓库 | 绷带 2（堆叠 count=2） |
| 首次行动 | 免费（默认配置即足够） |

### 10.3 商店商品（固定价）

| 商品 | 价格 |
|---|---|
| 绷带 | 40 |
| 医疗包 | 100 |
| 白手枪 | 120 |
| 白轻型护甲 | 150 |
| 白霰弹枪 | 260 |
| 白步枪 | 400 |

- 商店只卖 white；出售统一 `sellPrice`，**不支持撤销**。

### 10.4 资金保护（P0：触发时机修正）

- **基础资金底线（内置）**：`BASE_MONEY_FLOOR = 150`；`floor = BASE_MONEY_FLOOR + 100 × upgrades.money`。
- **补足触发时机**：**每个营地阶段开始且不存在有效局内行动时，触发一次补足**。营地阶段 = 新档首次加载营地（阶段标识 `'initial'`）或 某局结算完成回到营地（阶段标识 = 该局 `runId`）。
  - 条件：`Profile.floorApplyRunId !== 当前阶段标识` → 若 `money < floor` 则补足到 `floor`，并置 `floorApplyRunId = 当前阶段标识`。
  - **每个营地阶段只补足一次**：反复进出营地页不会重复补足（`floorApplyRunId` 已等于阶段标识）；新局结算后才进入新阶段。
- **效果**：玩家回到营地**即可获得资金**，先购买装备/补给，再开始行动——不会出现"想买手枪但没钱、进局只能徒手"的顺序冲突；也不会通过反复进出营地刷钱。
- 补足**不是**每局发放资金；超出 floor 的资金不受影响。

### 10.5 永久升级（消耗资金，立即生效）

| 升级 | key | 效果/级 | 级数 | 费用（逐级） |
|---|---|---|---|---|
| 背包扩容 | inv | +2 格（10→20） | 5 | 200 / 500 / 1200 / 2500 / 5000 |
| 生命强化 | hp | +10 最大生命（100→150） | 5 | 150 / 400 / 900 / 2000 / 4000 |
| 初始资金 | money | floor +100/级（150→650） | 5 | 100 / 250 / 600 / 1500 / 3000 |
| 初始补给 | supply | 开局携带医疗品 +1（0→3） | 3 | 150 / 400 / 1000 |

### 10.6 成就（P1：轻量长期目标）

| 成就 | 触发条件（结算时判定，§12.3） | 一次性奖励 |
|---|---|---|
| 初露锋芒 | 结算后累计撤离次数 ≥ 5 且未领取 | +300 |
| 猎杀者 | 结算后累计击杀精英 ≥ 3 且未领取 | +300 |
| 满载而归 | 本局 SUCCESS 结算物品总 value ≥ 500 且未领取 | +400 |
| 传说收藏家 | 本局携带 gold 装备撤离成功且未领取 | +500 |

- **计数来源**：击杀精英计数 = `RunState.killStats.elite`（局内击杀时记录），结算时并入 `Profile.milestones.eliteKills`；撤离次数 = 结算后 `Profile.extractions`。
- **发放时机**：成就判定在结算的 Settlement 计算阶段完成（§12.3 步骤 1），奖励金额写入 `Settlement.milestoneAwards`，与结算奖励在同一 Profile 快照内发放（§12.3 步骤 3）；重放时结果一致。

**验收（§10）**：资金 0 玩家回营地即可补足并购买最低装备；补足每营地阶段只一次；成就只发放一次；手动装配优先于自动装配。

## 11. 存档结构（P0）

### 11.1 键与版本

- `scsc_profile_v1`、`scsc_run_v1`。
- **版本迁移**：`loadProfile()` 读取时按当前结构合并默认值（缺字段补默认，多余字段忽略）；JSON 解析失败或结构非法 → 备份损坏内容至 `scsc_profile_corrupt` 后重置新档；`loadRun()` 同理。

### 11.2 Profile

```ts
type Profile = {
  version: 1;
  hp: number;                    // 营地最大生命（100 + 升级）
  money: number;                 // 资金
  stash: ItemInstance[];         // 仓库
  weapon: ItemInstance | null;   // 装备栏-武器
  armor: ItemInstance | null;    // 装备栏-护甲
  extractions: number; deaths: number; runs: number;
  upgrades: { inv: number; hp: number; money: number; supply: number };
  milestones: Record<string, number>;   // 成就计数（eliteKills 等）
  claimed: Record<string, boolean>;     // 成就已领取标记
  settledRunIds: string[];              // 已应用结算的 runId 集合（幂等锚点，§12.3）
  pendingStartRunId: string | null;     // 出发事务锚点（§15.4）
  floorApplyRunId: string;              // 最近已补足的营地阶段标识（§10.4）
};
```

### 11.3 RunState

```ts
type RunState = {
  version: 1;
  runId: string;                        // 唯一局 ID
  status: 'playing' | 'extracting' | 'settled';
  result: 'success' | 'dead' | 'mia' | null;   // settled 后的结局
  hp: number; maxHp: number;
  pos: { x: number; y: number };
  map: MapData;                         // 含 Crate[]，见 §11.6
  enemies: Enemy[];
  inventory: ItemInstance[];            // 局内背包（含补给+拾取物）
  weapon: ItemInstance | null; armor: ItemInstance | null;
  deadline: number;                     // 倒计时绝对时间戳（ms）
  pausedAt: number | null;              // 暂停开始时刻（暂停态非空，§15.3）
  modalPause: boolean;                  // 弹层暂停标志
  killStats: { elite: number };         // 局内击杀计数（成就来源）
  startSnapshot: StartSnapshot | null;  // 出发事务快照（§15.4）
  settlement: Settlement | null;        // 结算快照（§12.3）
};
```

### 11.4 Settlement（幂等结算快照，P0）

```ts
type Settlement = {
  runId: string;
  result: 'success' | 'dead' | 'mia';
  moneyDelta: number;        // 净资金变化（SUCCESS 为变现合计 + 成就奖励；DEAD/MIA 为成就奖励或 0）
  keptItems: ItemInstance[]; // SUCCESS：入库物品；DEAD/MIA：空
  destroyedCount: number;    // 销毁物品计数
  extras: { extractions: number; deaths: number; runs: number };
  milestoneAwards: Record<string, number>; // 本次成就奖励（§10.6）
  totalValue: number;        // 本局结算物品总 value（SUCCESS 成就「满载而归」判定依据）
};
```

### 11.5 StartSnapshot（出发事务快照，P0）

```ts
type StartSnapshot = {
  runId: string;
  movedItemIds: string[];   // 从 Profile 移入局内的物品 instanceId（武器/护甲/补给）
  floorAmount: number;      // 本次出发时应用的资金补足金额（可为 0）
};
```

### 11.6 Crate（箱子，P0：状态完整）

```ts
type Crate = {
  id: string;                        // crate_${x}_${y}
  kind: 'normal' | 'gold';
  state: 'unopened' | 'opening' | 'opened';
  openTicks: number;                 // 金箱引导进度（0..17）
  loot: ItemInstance[];              // 掉落物品（生成时确定；opened 后保留至全部拾取）
  x: number; y: number;
};
```

### 11.7 ItemInstance（P0）

```ts
type Rarity = 'white' | 'green' | 'blue' | 'purple' | 'gold';
type ItemCategory = 'weapon' | 'armor' | 'med' | 'junk';
type ItemInstance = {
  instanceId: string;   // `${templateId}_${timestamp}_${seq}`
  templateId: string;
  rarity: Rarity;
  affixes: string[];
  value: number;        // 单件价值（§6.4）
  count: number;        // 堆叠数量（仅 bandage/medkit 可 >1，默认 1）
};
```

- 类别由 `templateId` 推导：`weapon`（pistol/shotgun/rifle）、`armor`（light_armor/heavy_armor）、`med`（bandage/medkit）、`junk`（parts/chip/coin_stack）。

## 12. 游戏状态与结算规则（P0）

### 12.0 状态机（v4.1）

```
CAMP ─开始行动（出发事务）→ PLAYING ─进撤离点格→ EXTRACTING
PLAYING/EXTRACTING ─倒计时归零→ MIA（先判 SUCCESS）
PLAYING/EXTRACTING ─HP≤0→ DEAD
EXTRACTING ─引导完成→ SUCCESS
EXTRACTING ─离开撤离点格→ PLAYING
DEAD/MIA/SUCCESS ─结算（§12.3）→ settled → 清档 → CAMP（触发一次补足）
任意局内状态 ─弹层打开/onHide→ 暂停态（§15.3，倒计时冻结）
```

### 12.1 结算触发与幂等（P0）

- 结算入口 `finishRun(result)`，全流程按 §12.3 顺序执行。
- **同一 runId 只结算一次**：进入结算前检查 `RunState.settlement`（内存）与 `Profile.settledRunIds`（持久化集合），任一命中则直接返回。
- 结算期间不再响应攻击/治疗/移动输入；结算弹层打开 → 暂停态。

### 12.2 结算数据来源（P0：统一）

- **SUCCESS** 数据来源：`run.inventory`（全部：拾取物+剩余医疗品+杂物）+ `run.weapon/run.armor`。分类处理：装备类与医疗类 → 入库；杂物类 → 变现。
- **DEAD / MIA** 数据来源：`run.inventory` + `run.weapon/run.armor` → 全部销毁。
- **物品只结算一次**：入库与变现互斥；已入库物品不再进入变现统计。

### 12.3 结算持久化顺序（P0：单快照原子应用）

```
finishRun(result):
 1. 计算 Settlement（纯内存）：含成就判定（依据 Profile 累计 + RunState.killStats + 本局条件）
 2. 持久化 RunState：status='settled', result, settlement（写 scsc_run_v1）      ← 先落结算标记
 3. 持久化 Profile：在【同一快照】内完成——
      a. 应用 moneyDelta（变现 + 成就奖励）
      b. 入库 keptItems（堆叠合并）
      c. 更新战绩（extractions/deaths/runs）
      d. 发放成就奖励并置 claimed
      e. 触发本营地阶段资金补足（§10.4，置 floorApplyRunId = runId）
      f. 追加 runId 到 settledRunIds
      g. pendingStartRunId = null
    （写 scsc_profile_v1）                                                    ← 再落结算结果（原子）
 4. clearRun（移除 scsc_run_v1）                                                ← 最后清档
```

- **恢复兜底**（进入 game 页时，§15.2）：读到 RunState 为 settled 且 `runId ∉ Profile.settledRunIds` → 说明步骤 2 已落、步骤 3 未落（中途崩溃）→ **重放 settlement**：按步骤 3 的同一快照逻辑应用（含 a–g），持久化 Profile；若 `runId ∈ settledRunIds` → Profile 已应用，只展示结算页。
- **强约束**：Settlement 只能来自当前 RunState（`scsc_run_v1`）；`clearRun` 后旧 Settlement 不可再被加载；`settledRunIds` 集合而非单值，杜绝「旧局 Settlement 覆盖锚点后被误重放」。
- **原子性**：步骤 3 的 a–g 必须在一次 `writeStorage` 内完成（同一 Profile 对象一次写入），不允许分步写。

**验收（§12）**：同一 runId 只结算一次；步骤 2/3 之间崩溃重启后结算恰好一次；旧局 Settlement 无法被再次加载执行；步骤 3 为单快照原子写入。

## 13. 物品与经济规则（P0）

### 13.0 归属与入账定义（P0）

- 位置：`stash` | `weapon` | `armor` | `run.inventory` | `run.weapon/armor`；**转移即移动引用**，任何位置不得同时持有同一 `instanceId`；装备栏物品不占仓库格。
- 入账：**变现 = 折算资金并销毁**；**入库 = 保留实物移入 stash**；一件物品一生最多结算一次（变现 XOR 入库，且仅发生在 SUCCESS 结算或营地出售时）。

### 13.1 生命周期（P0）

| 阶段 | 规则 |
|---|---|
| 出发（§15.4） | `startSnapshot` 记录移入局内的物品 id 与补足金额；Profile 扣除与 RunState 建立按 §15.4 顺序原子完成 |
| 局内拾取 | 拾取物入 `run.inventory`（背包满 → §13.6）；`Crate.loot` 同步移除 |
| 局内使用 | 医疗品从 `run.inventory` 消耗（堆叠拆分，§13.5） |
| SUCCESS | `run.inventory`：装备/医疗 → 入库 stash（堆叠合并）；杂物 → 变现；`run.weapon/run.armor` → 入库 stash |
| DEAD/MIA | `run.inventory`、`run.weapon/run.armor` 全部销毁 |
| 营地出售 | `stash` 物品按 `sellPrice` 得钱并销毁（二次确认） |
| 营地丢弃 | `stash` 物品销毁（二次确认） |

### 13.2 资金

- 来源：SUCCESS 变现、出售仓库物品、成就奖励、资金补足（仅营地阶段开始，§10.4）。
- 去处：商店购买、营地升级。
- `money` 为非负整数，无上限。

### 13.3 容量

- 局内背包：`10 + inv×2`（上限 20）；仓库无硬上限（首版）。

### 13.4 结算分类（P0）

- `weapon`/`armor` 模板 → **装备类（入库）**；`bandage`/`medkit` → **医疗类（入库）**；`parts`/`chip`/`coin_stack` → **杂物类（变现）**。
- 已装备物（`run.weapon/run.armor`）在 SUCCESS 时一律入库（回到仓库，营地按手动/自动装配下一局），**不参与变现**。

### 13.5 堆叠与拆分（P0）

- 仅 `bandage`/`medkit` 可堆叠（同模板同品质合并，`count` 累加，占 1 格；价值 = `value × count`）。
- **拆分**：消耗/带入/出售/入库需要部分数量时，原实例拆为两份（保留原 `instanceId` 的为剩余部分，新生成 `instanceId` 的为被拆分部分）；计数为 0 的实例立即移除。
- 堆叠物品结算：入库时与 stash 同模板同品质堆叠合并；变现按 `value × count`。

### 13.6 背包满时开箱（P1）

- 开箱产出放不下 → 「替换/放弃」弹层（暂停态）：显示新物品与背包；**替换**（选一件背包物品丢弃并拾取新物）/ **放弃**（新物销毁，可关闭弹层）。
- **未领取物品保存在 `Crate.loot`**：弹层关闭后物品仍在箱子中（`state='opened'` 但 `loot` 未清空），玩家可再次进入箱子格拾取；全部拾取后 `loot` 清空。
- 堆叠物品在背包满判断中按「1 格」计。

### 13.7 开箱状态机（P0）

```
unopened ─进入箱子格→ opening（仅 gold；normal 直接跳 opened）
opening ─openTicks 累计满 17→ opened（loot 可领取）
opening ─离开格子/受击→ 回退 unopened（openTicks=0）
opened ─拾取全部 loot→ loot 清空（箱子完成，不再交互）
```

- `normal` 箱子：进入格即 `opened`（无引导）。

**验收（§13）**：任意物品不复制/不丢失/不重复计价；堆叠拆分后总数守恒；SUCCESS 后物品只入库一次或只变现一次；死亡后仓库物品不变；未领取物品保留在箱子可再拾取。

### 15.1 版本迁移

- §11.1：合并默认值 + 损坏重置（备份损坏内容）。

### 15.2 统一恢复入口 `restoreRun()`（P0：顺序固定）

进入 game 页 `onLoad` 后按以下顺序执行，**不跳步**：

1. **读档**：`loadRun()`。
2. **无档** → 走出发事务生成新局（新 runId）并持久化 → 开始 PLAYING。
3. **有档且 `status === 'settled'`**：
   a. 读 `Profile.settledRunIds`；
   b. `runId ∈ settledRunIds` → 直接展示结算页（不重放）；
   c. 否则 → **重放 `settlement` 到 Profile**（§12.3 步骤 3 同一快照逻辑：a–g），持久化 → 展示结算页。
4. **有档且未 settled**：
   a. **出发事务恢复**：若 `startSnapshot` 存在且 `Profile.pendingStartRunId !== runId` → 应用扣除（从 Profile 移除 `movedItemIds`），置 `pendingStartRunId = runId`，持久化；
   b. **暂停补偿**：若 `pausedAt` 非空 → `deadline += (now − pausedAt)`，`pausedAt = null`，持久化；
   c. **倒计时判定**：若 `deadline <= now`（补偿后仍过期）→ 按 MIA 走 §12.3 结算；
   d. 否则恢复 PLAYING/EXTRACTING（按原 status 继续）。
5. 恢复后检查 `modalPause`：为 true 则暂停态继续生效。

### 15.3 统一暂停/恢复（P0：多原因重叠只补偿一次）

- **暂停态判定**：`pausedAt !== null`。进入暂停态的唯一入口 `pauseGame()`；退出唯一入口 `resumeGame()`。
- `pauseGame()`：若 `pausedAt === null` → `pausedAt = now`（记录开始时刻），清理主循环。
- `resumeGame()`：若 `pausedAt !== null` → `deadline += (now − pausedAt)`，`pausedAt = null`，恢复主循环。
- **多原因重叠**：弹层打开时已暂停（pausedAt 非空），此时 `onHide` 再次调用 `pauseGame()` → **不覆盖 pausedAt**（保持最早开始时刻）；`onShow` 后弹层仍开 → 不调用 `resumeGame()`；弹层关闭 → `resumeGame()` 一次性补偿全部暂停时长。规则：**pausedAt 只在 null→非 null 时记录，只在 非 null→null 时补偿**。
- **钩子映射**：
  - 弹层打开 → `pauseGame()`；弹层关闭 → 若 `pausedAt` 非空且非后台恢复场景 → `resumeGame()`。
  - `onHide` → `pauseGame()`（若未暂停）+ 持久化 RunState。
  - `onShow` → 若 `modalPause=false` 且 `pausedAt` 非空 → `resumeGame()`；若 `modalPause=true` → 保持暂停（等弹层关闭时补偿）。
  - `onUnload` → 清理定时器；保留 RunState 存档（供下次恢复）。
- 长时间离线（`onShow` 距 `pausedAt` > 24h）：仍按暂停处理（离线版友好，无额外惩罚）。

### 15.4 出发事务 `startRun()`（P0：与结算同等保护）

从营地点击「开始行动」时执行，持久化顺序固定：

```
startRun():
 1. 计算：runId、RunState（含装配 weapon/armor、扣除 supply 后入 inventory、startSnapshot）
 2. 持久化 RunState（写 scsc_run_v1）                                          ← 先落局内状态
 3. 持久化 Profile：【同一快照】扣除 movedItemIds（weapon/armor 置 null、stash 扣 supply、
    拆堆叠）、应用本次 floorAmount 补足并置 floorApplyRunId=runId、
    置 pendingStartRunId=runId（写 scsc_profile_v1）                            ← 再落扣除
 4. navigateTo game 页
```

- **崩溃恢复**：步骤 2 后、步骤 3 前崩溃 → 重启后 `restoreRun()` 检测 `pendingStartRunId !== runId` → 按 `startSnapshot` 补执行步骤 3 的扣除与补足（同一快照），置 `pendingStartRunId = runId`。
- **防重复装配**：`restoreRun()` 或营地加载时，若存在 `status !== 'settled'` 的 RunState 且 `pendingStartRunId === runId` → 视为已出发，提供「继续行动」入口（不重复装配、不重复扣除）。
- 结算完成后 `pendingStartRunId = null`（§12.3 步骤 3-g）。

**验收（§15）**：出发与结算的跨存档转移在任意崩溃点恢复后均不重复、不丢失；暂停多原因重叠只补偿一次；退出重进可恢复；倒计时暂停期间不流逝；损坏存档重置不崩溃。

## 16. 数值平衡与测试（P1 目标 + 待实测）

### 16.1 战斗推演（P0：修正后的假设）

> 假设 3 房间、普通敌人 6（≈4 近战 + 2 远程）+ 精英 1；敌人行动周期 480ms；攻击间隔按 §6.2 tick。

| 场景 | 计算 |
|---|---|
| 白手枪 vs 近战(25HP) | 10×3 = 3 次（6 tick/次） |
| 白手枪 vs 远程(18HP) | 10×2 = 2 次 |
| 白霰弹枪 vs 近战 | 20×2 = 2 次（8 tick/次） |
| 白步枪 vs 近战 | 16×2 = 2 次（7 tick/次） |
| 白手枪 vs 精英(60HP) | 6 次；霰弹 3 次；步枪 4 次 |
| 轻甲(2) 被近战命中 | max(1, 8−2) = 6 伤 |
| 重甲(4) 被近战命中 | 4 伤 |
| 重甲(4) 被精英冲锋 | max(1, 15−4) = 11 伤 |
| 2 近战集火轻甲 | 12 伤 / 480ms → 100HP 约 4.0s |
| 治疗 | 绷带 15（5 tick）；医疗包 35 |

- 结论：3 房间约 7 敌，玩家需走位风筝；开局 100HP + 2 绷带可支撑 1 次集火失误；精英需拉锯 6 次手枪攻击，建议优先躲冲锋、利用霰弹/步枪爆发。

### 16.2 经济推演（P0：v4.1 规则下的模型）

- 普通箱 3 房间 ≈ 4.5 件掉落；按品质加权（系数期望 ≈ 1.71，平均模板价值 ≈ 180 → 单件 ≈ 307）。
- SUCCESS 分配：装备类/医疗类入库（可出售换钱），杂物类变现（≈ 30–120/件）。
- 玩家出售不需要的装备：`sellPrice ≈ value×0.5 ≈ 150/件`。
- **单局成功现金收益估算** ≈ 杂物变现 60–120 + 卖出 1–2 件装备 150–300 ≈ **250–420 资金**（若保留装备则现金更少）。
- 商店成本：白手枪 120 / 白步枪 400；升级第 1 级 100–200。
- 节奏：成功 2–3 局 → 1 把好武器 或 1 级升级 + 补给；金箱/精英高风险高回报（blue+ 装备入库，出售价更高）。
- 死亡局：损失本局装备价值（≈300–600）与变现机会；仓库与资金保留 → 靠补足 + 手动/自动装配 + 徒手继续，**不死循环**。

### 16.3 待实测指标（首版上线后统计，不预调数值）

| 指标 | 初始测试目标 |
|---|---|
| 普通局平均时长 | 3–5 分钟 |
| 新手撤离成功率 | 50%–70% |
| 成功撤离平均搜刮房间数 | 2–3 个 |
| 金箱开箱成功率 | 20%–50%（高风险验证） |
| 因规则/状态错误导致的异常结算 | 0 次 |
| 死亡局「背包满无法继续」占比 | < 10% |
| 远程敌人「贴脸后退再攻击」行为可观测率 | ≥ 90%（行为验收） |

**三项体验观察（P1，原型验证，不据此扩功能）**：
1. **搜刮是否值得冒险**：玩家能否感知普通箱 vs 金箱奖励差异；金箱高品质奖励是否足以抵消守卫/开箱时间/撤离失败风险。
2. **玩家是否有路线选择**：随机地图是否产生「绕路避战 vs 直冲」的真实选择；若体验仍线性，先调地图房间连通结构，不新增系统。
3. **玩家是否害怕失去装备**：死亡损失与补足保护是否形成「带好装备的恐惧感」而非「无脑冲金箱」；通过游玩调整经济保护与稀有度。

- 调优原则：一次只调一个变量（地图尺寸/敌人数量/掉落率/倒计时/floor），实测驱动。

### 16.4 尚待实测的数值假设（P0：显式列出）

1. 240s 倒计时与 3 房间全搜是否平衡（超时率目标 < 30%）。
2. 6 普通 + 1 精英对新手强度（撤离成功率目标 50%–70%）。
3. `BASE_MONEY_FLOOR = 150` 的破产恢复能力（连续 3 局死亡后仍能购置最低装备）。
4. 金箱 17 tick 引导与守卫强度是否形成「值得冒险」而非「必死陷阱」。
5. 背包 10 格 + supply 医疗品的占位体验。
6. 远程「先退后攻」行为是否过于保守（若远程几乎无法命中玩家则放宽后退阈值）。
